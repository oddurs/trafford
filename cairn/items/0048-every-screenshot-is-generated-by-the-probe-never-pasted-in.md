## Problem

A terminal application is sold by what it looks like, so the page needs
screenshots. Pasted-in screenshots are a lie with a timer on them: the ASCII
frame in `README.md` was true when it was written, and nothing fails if the
status bar changes tomorrow. A landing page carrying an interface the program
no longer has is worse than one carrying none.

There is already a machine that knows what the program draws. `tools/probe.py`
runs the real binary against an emulated terminal, reads the screen back, and
can render it out as HTML with the colours each cell actually got.

## Proposal

Make every image on the site a build product.

- **A manifest, not a script per shot.** `site/shots.toml` lists each shot: a
  vault fixture, a size, a sequence of keys, a name. One entry is one image.
- **The probe renders it to SVG**, with real text — selectable, searchable,
  scaling to any display, a few kilobytes, and diffable in a pull request in a
  way a PNG is not.
- **Committed, and checked.** The SVGs live in the repo so a site build needs
  no Python and no terminal. CI regenerates them and fails if they differ,
  which is the whole point: a change to the status bar shows up as a changed
  screenshot in the diff of the commit that caused it.
- **The fixture vault is fixed.** Generated by `trafford init` plus a handful
  of committed notes, so a shot never depends on someone's real vault, on the
  time of day in the status bar, or on git state.

## Acceptance criteria

- [ ] `make shots` — or whatever the workspace's equivalent is — regenerates
      every image from the real binary
- [ ] CI fails when a committed shot no longer matches what the program draws
- [ ] A shot is deterministic: the clock, the git state and the terminal size
      are all pinned
- [ ] Images are legible at 320px wide and are not a horizontal scrollbar on a
      phone
- [ ] The site build does not require Python

## Notes

The clock in the status bar is the obvious non-determinism and the git branch
is the one that gets missed — a shot taken on `worktree/rapid-field-1e56`
carries that branch name into the page.

An asciinema cast of the file tree opening is worth more than any still, and it
is the same mechanism with the frames kept. Not now: one still pipeline that
works beats two half-built ones, and #0067 needs `Range` support before a
cast player is comfortable anyway.
